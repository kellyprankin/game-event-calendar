# AI notes

Running log of AI output that was rejected or had to be fixed. Feeds the README's AI usage note.

- **Template seeding with `HasData` (Phase 1).** Claude Code first seeded the game templates with EF Core `HasData`. The generated migration looked fine, but the app crashed on startup with `PendingModelChangesWarning`: EF compares the seeded `Formats` lists by reference, so every build reported a model change. Caught by actually running `docker compose up` rather than trusting a successful build. Fixed by switching to EF's `UseSeeding`/`UseAsyncSeeding` hooks, which insert missing templates at startup.
- **Past-date blocking on the create form (Phase 3 follow-up).** Asked to stop events being created in the past, Claude Code set `min` on the `datetime-local` input. In manual testing today's date appeared greyed out, and Claude Code's first "fix" (min = midnight) was a guess about the picker's behavior that changed nothing visible. It later turned out the grey was likely just Chromium's highlight for today rather than a disabled day. The lesson was to check what the UI is actually doing before patching it. The form now uses separate `date` (min = today) and `time` inputs, which behave predictably across browsers; the submit-time check and the server's rule remain the real guarantee against past dates.
