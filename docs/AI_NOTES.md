# AI notes

Running log of AI output that was rejected or had to be fixed. Feeds the README's AI usage note.

- **Template seeding with `HasData` (Phase 1).** Claude Code first seeded the game templates with EF Core `HasData`. The generated migration looked fine, but the app crashed on startup with `PendingModelChangesWarning`: EF compares the seeded `Formats` lists by reference, so every build reported a model change. Caught by actually running `docker compose up` rather than trusting a successful build. Fixed by switching to EF's `UseSeeding`/`UseAsyncSeeding` hooks, which insert missing templates at startup.
- **Past-date blocking on the create form (Phase 3 follow-up).** Asked to stop events being created in the past, Claude Code set `min` on the `datetime-local` input to the current time. In manual testing, today couldn't be chosen: the form defaulted to 6:00 PM, and once that had passed, "today at 6:00 PM" was below `min`, so the picker blocked the day. Claude Code's next change (min = midnight) fixed the logic, but it was a guess, and today still *looked* disabled. Claude Code then asserted from memory that the grey was Edge's "today" highlight. Pushed to verify, it tested the input's validity in headless Edge (today was valid) and checked a screenshot of the picker: past days are a darker disabled grey, today a slightly lighter highlight. The lesson was to verify browser behavior instead of reasoning about it. The form now uses separate `date` (min = today) and `time` inputs; the submit-time check and the server's rule remain the real guarantee against past dates.
